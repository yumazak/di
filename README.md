# di

ローカルの git 差分をブラウザで見る CLI。

```bash
di .
```

でブラウザが開き、そのリポジトリの**コミットしていない変更**が
[`@pierre/diffs`](https://www.npmjs.com/package/@pierre/diffs)（[DiffsHub](https://diffshub.com/) と同じ
CodeView コンポーネント）で表示される。ファイルを編集すると自動で更新される。

```
di . → git diff → HTTP/SSE → ブラウザ (React + @pierre/diffs CodeView)
```

バックエンドは Go、フロントは React + Vite。フロントはビルド後に gzip して
バイナリへ埋め込むので、**成果物は 8.0MB の実行ファイル 1 つ**になる。
実行に必要なのは `git` だけで、Node もランタイムも要らない。

## インストール

[mise](https://mise.jdx.dev/) の GitHub backend で入れる。

```bash
mise use -g github:yumazak/di
```

直接落とす場合は [Releases](https://github.com/yumazak/di/releases) から。

```bash
# macOS (Apple Silicon)
curl -sL https://github.com/yumazak/di/releases/latest/download/di_darwin_arm64.tar.gz | tar xz
mv di ~/.local/bin/di
```

`di_darwin_amd64` / `di_linux_amd64` / `di_linux_arm64` も同じ URL の形で置いてある。
チェックサムは同じリリースの `SHA256SUMS` で確認できる。

## 必要なもの

実行するだけなら **`git` だけ**。ビルドには次が要る。

- Go 1.25+
- Node.js 20.19+ と pnpm 10（フロントのビルド用）

## セットアップ

```bash
pnpm install
pnpm build      # vite build → gzip → go build
```

`dist/di` が単一バイナリ。PATH の通った場所へ置けばどこからでも使える。

```bash
cp dist/di ~/.local/bin/di
```

## 使い方

```
di [path] [options]

引数:
  path              リポジトリ内の任意のパス（既定: .）

オプション:
  -p, --port <n>    使用するポート（既定: 空きポートを自動選択）
      --host <h>    バインドするホスト（既定: 127.0.0.1）
      --no-open     ブラウザを自動で開かない
  -h, --help        ヘルプ
```

パスはリポジトリ内ならどこでもよく、`git rev-parse --show-toplevel` でルートに解決される。
サブディレクトリを指定してもリポジトリ全体の差分が出る。

### 別の端末（スマホなど）から見る

既定では `127.0.0.1` にしかバインドしないので、他の端末からは繋がらない。`--host` で
バインド先を明示する。

Tailscale 越しに見る場合は、`0.0.0.0` ではなく**自分の Tailscale IP を指定する**のが安全。
`0.0.0.0` にすると同じ LAN にいる全員からも見えてしまう。

```bash
tailscale ip -4                        # 例: 100.94.126.82
di . --host 100.94.126.82 --port 7788
```

これで MagicDNS 名（`http://<マシン名>.<tailnet>.ts.net:7788/`）からも開ける。
ポートを固定しているのは、スマホ側で URL を打ち直さなくて済むようにするため。

`di` には**認証が一切ない**。バインドした範囲から到達できる相手には、そのリポジトリの
差分がすべて読める。

### 画面

サイドバーは VS Code と同じ形。左端のアクティビティバーで「ソース管理 / ファイル /
コメント」を切り替え、**選択中のアイコンをもう一度押すとパネルが閉じる**（レールだけ残る）。
選んだビューと開閉は `localStorage` に残る。既定はソース管理で、ファイラは畳んだ状態。

| ビュー         | 内容                                                                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ソース管理     | 「ステージ済み」「変更」のアコーディオン。見出し左の `⌄` で畳み、見出しを押すとそのセクションの差分に切り替わる                                            |
| └ ステージ済み | `git diff --cached` の内容。行ホバーの `−` と、見出しの `−` ボタンでステージから出せる                                                                     |
| └ 変更         | `git diff` + 未追跡ファイル。行ホバーの `+` と、見出しの `+` ボタンでステージに入れられる。ゴミ箱ボタンで全部破棄                                          |
| ファイル       | リポジトリ全部のツリー（[`@pierre/trees`](https://www.npmjs.com/package/@pierre/trees)）。既定は畳んだ状態。虫めがねで検索、じょうごで git status 絞り込み |
| コメント       | 付けたコメントの一覧（ファイルごと）とコピー                                                                                                               |

パネルの最下段には集計（ファイル数・追加・削除・表示済み）が常に出る。`F2` で開閉。

上部にはリポジトリ名・ブランチ・HEAD・自動更新インジケータ（緑＝接続中）、**いま見ている
対象**、レイアウト切り替え、再取得、テーマ、表示設定が並ぶ。

### テーマと表示設定

トップバー右の 2 つのアイコンから設定する。選択内容は `localStorage` に残る。

| メニュー | 内容                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- |
| テーマ   | 自動 / ライト / ダーク、およびライト・ダークそれぞれの Shiki テーマ（pierre-\* と Shiki 同梱の全部） |
| 表示設定 | 背景を塗る / 行番号 / 折り返し / 差分の印（バー・`+ −`・なし）                                       |

テーマはコードのハイライトだけでなく、サイドバーやトップバーの配色にも反映される。
テーマの `sideBar.background` などから、背景に対して十分読める前景色を選び、その色を
背景に混ぜて枠線やホバー面を作っているので、どのテーマを選んでも破綻しない
（`src/web/theme.ts`）。

### フォント

diffshub と同じ組み合わせ（UI は Geist、コードは Berkeley Mono）を狙っているが、
**Berkeley Mono は有償フォントなので同梱できない**。そこで等幅は段階的に落とす。

```
"Berkeley Mono" → "TX-02" → "JetBrains Mono Variable"（同梱）→ ui-monospace → ...
```

持っていれば diffshub と同じ見た目になり、無ければ同梱した JetBrains Mono になる。
UI の Geist と JetBrains Mono はどちらも SIL OFL 1.1 で、**latin サブセットだけを
バイナリに同梱**している（2 ファイルで約 70KB）。日本語はどちらも glyph を持たないので
OS のフォントへ落ちる。

CDN から読まないのは、オフラインや Tailscale 越しで開いたときに読めなくなるうえ、
差分を開くたびに外部へリクエストが飛ぶため。CodeView（shadow DOM）にも
`--diffs-font-family` / `--diffs-header-font-family` で同じフォントを渡している。

### キーボードショートカット

| キー | 動作                         |
| ---- | ---------------------------- |
| `d`  | split / unified の切り替え   |
| `c`  | 差分をすべてたたむ / 開く    |
| `F2` | サイドバー最下段の集計を開閉 |

入力欄にフォーカスがあるときは効かない。

### 狭い画面

幅 760px 以下ではサイドバーが差分の上に積まれ、差分は設定に関わらず 1 カラム
（unified）で描かれる。スマホから見るときに 2 カラムだと読めないため。

### ファイル単位の折りたたみと「表示済み」

GitHub のレビュー画面と同じ操作にしてある。

- ファイルヘッダ左の `⌄` でそのファイルだけ折りたたむ。畳んだファイルが画面の上に
  出ているときは、そのファイルの頭へスクロールを合わせ直すので見失わない
- ヘッダ右の **`表示済み`** を押すと、GitHub の Viewed と同じく**自動で畳まれる**。
  もう一度押すと開く
- **トップバーの折りたたみボタン**（`c` キー）で、出ている差分をまとめて畳む／開く。
  サイドバーのセクションを畳むアコーディオンとは別物なので、置き場所を分けてある
- 進捗は見出しに `3/17` のように出る。表示済みのファイルはサイドバーでも薄くなる
- 表示済みはリポジトリごとに `localStorage` に残る（折りたたみは一時的な状態なので残さない）

本体に出るものは 3 つのどれかで、混ざらない。

| 選択                      | 表示                                                 |
| ------------------------- | ---------------------------------------------------- |
| 見出し `変更`（初期状態） | `git diff` の差分だけを 1 スクロールで（仮想化あり） |
| 見出し `ステージ済み`     | `git diff --cached` の差分だけを 1 スクロールで      |
| セクション内のファイル    | そのセクションに切り替えて、該当ファイルへスクロール |
| ツリーのファイル          | 変更の有無にかかわらず、そのファイルの全文           |

**ステージ済みと未ステージを同じスクロールに混ぜない**のが要点。混ぜると、両方に変更が
あるファイルが同じ名前で 2 回並び、どちらの差分を読んでいるのか分からなくなる。VS Code
と同じく、見る対象を切り替える形にしてある。いま何を見ているかは、上部の表示と、
サイドバーで選択中のセクションに付く左の帯で分かる。

差分を見る場所はこの 2 つだけで、**ツリーは常にファイルそのものを出す**。変更のある
ファイルをツリーから開いても差分にはならない。その差分が見たいときは変更一覧から選ぶ。

見ているセクションが空になったら中身のある方へ自動で移る（全部ステージしたら
「ステージ済み」へ、全部解除したら「変更」へ）。

ツリーに出るのは tracked + untracked で、`.gitignore` は尊重する。どの表示でも行番号
クリックでコメントできる。

### ステージ操作

VS Code のソース管理と同じく、**ファイル単位**（行にホバーすると出る `+` / `−`）と
**一括**（見出しの `+` / `−` ボタン）でステージを操作できる。未追跡ファイルもそのまま
`+` で追加できる。見出しのボタンをアイコンにしているのは、パネル幅 262px に文言のボタンを
並べると折り返してしまうため。ホバーで `すべてステージ` などの説明が出る。

```
POST /api/stage  {"paths": ["src/a.ts"], "staged": true}
```

- `staged: true` → `git add --`
- `staged: false` → `git reset --`

解除に `git reset` を使うのは、他の候補がどちらも落とし穴を踏むため。

| コマンド               | 問題                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| `git restore --staged` | コミットが 1 つも無いと `fatal: could not resolve HEAD`                                      |
| `git rm --cached`      | index の内容がファイルとも HEAD とも違うと拒否される（add した後にファイルを消した場合など） |

`git reset` はどちらの状況でも worktree を触らずに index だけ戻せる。

ステージ済みと未ステージは別々の表示なので、どちらの差分を見ているかで迷わない。
hunk 単位・行単位のステージには対応していない。

### 変更の破棄

「変更」セクションの行にホバーすると出るゴミ箱と、見出しのゴミ箱ボタン。VS Code と同じく
**取り消せない**ので、実行前に必ず確認ダイアログを出す。

```
POST /api/discard  {"paths": ["src/a.ts"]}
```

対象の状態によって処理が変わる。

| 状態               | 処理                                            |
| ------------------ | ----------------------------------------------- |
| 追跡済みで変更あり | `git restore --worktree`（index の内容へ戻す）  |
| 追跡済みで削除済み | 同上（ファイルが復活する）                      |
| 未追跡             | ファイルを削除（git に「戻す」概念が無いため）  |
| ステージ済み       | **触らない**。捨てられるのは add 後の編集分だけ |

### コメント

行にホバーすると**ガターに「+」**が出る。GitHub と同じで、

- **クリック** → その 1 行にコメント
- **ドラッグ** → 範囲を選んで複数行にコメント

タッチ環境ではホバーが無いので、**行番号のタップ**でも開く。`⌘/Ctrl+Enter` で保存、
`Esc` で取り消し。保存したコメントは diff の中にインラインで表示され、サイドバーの
コメントタブにも一覧される。

サイドバーの `コピー` を押すと、全コメントがこの形式でクリップボードに入る。

```
README.md:3 この一文いらないかも
src/app.ts:8-9 この2行まとめて直したい
src/app.ts:13 reduce だと初期値の型が曖昧
  明示した方がよさそう
```

- 複数行を選んだコメントは `パス:開始-終了` になる
- パス順・行番号順にソートされる
- 本文が複数行のときは 2 行目以降を 2 スペースでインデントし、行頭が常に `パス:行数` になるようにしている
- コメントはリポジトリごとに `localStorage` に保存されるので、リロードしても消えない
- split の**左カラム（削除行）**にコメントすると、行番号は**変更前**のファイルのものになる。
  その場合はカードに「変更前の行」と表示される（コピーされる文字列は同じ `パス:行数` 形式）

#### `http://` 経由（スマホなど）での注意

`http://127.0.0.1` 以外の HTTP は**セキュアコンテキストではない**ため、一部のブラウザ API が
使えない。踏んだものは対処済み。

| API                   | 非セキュアでの挙動                                          | 対処                                                                                        |
| --------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `crypto.randomUUID()` | 未定義。呼ぶと例外 → 画面が真っ白（ダークだと真っ黒）になる | `crypto.getRandomValues` で ID を生成                                                       |
| `navigator.clipboard` | 未定義                                                      | `document.execCommand("copy")` へフォールバック。それも失敗したら選択済みの textarea を出す |

例外で画面が消えると原因が分からないので、エラーバウンダリを置いてメッセージを出すようにしてある。

### 表示される差分

`git diff HEAD` 相当（**staged + unstaged**）に、**未追跡ファイル**を新規ファイルの diff として
足したもの。要するに「今コミットしたら入る変更」がそのまま出る。

未追跡ファイルは `git diff --no-index /dev/null <file>` で patch 化している。
バイナリと 1MB 超のファイルは除外し、画面上部に除外した旨を出す。

### ライブリロード

サーバが 700ms ごとに変化を見て、差分が変わっていたら SSE でブラウザに通知する。
通知を受けたブラウザは `/api/diff` を取り直して再描画する。

`fs.watch` ではなく git のポーリングにしているのは、`.git` の中身・エディタの一時ファイル・
`.gitignore` の扱いを自前で判断すると結局 git を叩き直すことになるため。
ポーリングは**ブラウザが開いている間だけ**動く（SSE の購読者がゼロになったら止まる）。

ポーリングのたびに patch を作り直すと重いので、2 段構えにしている（[パフォーマンス](#パフォーマンス)参照）。

## パフォーマンス

素朴に作ると重くなる箇所がいくつかあったので、対処してある。

### 配布サイズ

フロントは 12.1MB あるが、そのうち **10.3MB は shiki の言語チャンク 318 個**で、コアは
1.8MB しかない。全部 gzip すると **2.3MB** まで落ちるので、gzip したまま埋め込み、
`Content-Encoding: gzip` でそのまま返している（gzip を受け付けないクライアントには
その場で展開）。転送量も小さくなる。

バックエンドの言語も測ったうえで選んだ。

| 方式                                              | バイナリ      |
| ------------------------------------------------- | ------------- |
| Node SEA                                          | 約 110MB      |
| Bun `--compile`                                   | 72MB          |
| **Go（採用）**                                    | **8.0MB**     |
| [scriptc](https://github.com/vercel-labs/scriptc) | 約 3MB 見込み |

scriptc（TypeScript を JS エンジン無しでネイティブ化する実験的コンパイラ）も試した。
`scriptc coverage` では型エラーを 11 個直したうえで **92%（257/277 文）が静的コンパイル可能**
だったが、`fs/promises` に `realpath` が無くパストラバーサル対策の強度を落とさざるを得ない
点と、v0.0.22 という段階を踏まえて見送った。

### サーバ: ポーリングを 2 段構えにする

`CollectDiff()` は未追跡ファイル 1 件につき `git diff --no-index` を 1 プロセス起動する。
このリポジトリ（未追跡 28 件）での内訳は次のとおりで、9 割以上が未追跡ループだった。

| 処理                           | 時間    |
| ------------------------------ | ------- |
| `git diff HEAD`                | 9.7ms   |
| `git status --porcelain -uall` | 15.3ms  |
| 未追跡ループ（28 プロセス）    | 303.8ms |

数字は TypeScript 版で測ったものだが、コストの実体は git のプロセス起動なので Go でも同じ。
これを 700ms ごとに回すとブラウザを開いている間ずっと CPU を食うので、

1. **安い署名**（`git status` 1 プロセス + 変更のあったファイルの `mtime`/`size`）で変化を検知
2. 署名が動いたときだけ `CollectDiff()` を実行
3. 未追跡ファイルの patch は `(path, mtime, size)` でキャッシュし、変わった 1 件だけ再 diff

`git status` の出力だけだと「すでに変更済みのファイルをもう一度編集した」ケースを取りこぼす
ので、署名には mtime と size も混ぜている。

|                        | 対処前 | 対処後   |
| ---------------------- | ------ | -------- |
| 定常時のポーリング     | 330ms  | **17ms** |
| 変更後の `CollectDiff` | 330ms  | **35ms** |

### クライアント: 再描画をファイル単位にする

`CodeView` はアイテムの `id` + `version` でしか更新を判定しない。逆に言えば version を
据え置けば触らないので、**中身か注釈が実際に変わったファイルだけ** version が動くようにしている
（`src/web/versions.ts` の内容ハッシュ + パスごとの注釈バージョン）。

ただし version を安定させるだけでは足りず、`options` と `renderAnnotation` の identity も
固定する必要がある。これらが毎レンダー変わると、全アイテムが作り直されてしまう。そのため

- `useComments` の操作系コールバックは全部 ref 経由にして identity を固定
- 下書きの内容は注釈の `metadata` に載せ、`renderAnnotation` がクロージャで `draft` を
  掴まないようにする

としている。結果、**コメントを 1 件足しても、無関係なファイルを編集しても、他のファイルの DOM は
作り直されない**（`data-probe` 属性が生き残ることで確認済み）。

### クライアント: ハイライトをワーカーへ

`WorkerPoolContextProvider` でワーカープールを張っている（`src/web/main.tsx`）。
`langs` は事前ロードのヒントでしかなく、載っていない言語は実行時に解決されるので指定していない。

### クライアント: 無駄な再取得を握りつぶす

`/api/files` と `/api/file` は差分が変わるたびに取り直すが、中身が同じなら state を
差し替えない（`useStableJson`）。ツリーの `resetPaths` や、開いているファイルの再ハイライトが
無駄に走るのを防ぐため。

## 開発

```bash
pnpm dev         # Vite dev server (5173) + Go の API サーバ (7777) を並列起動
pnpm build       # フロントをビルド → gzip → dist/di を出力
pnpm typecheck   # tsc --noEmit（フロント）
pnpm lint        # oxlint（フロント）
pnpm fmt         # oxfmt（フロント）
pnpm vet         # go vet（バックエンド）
```

`pnpm dev` の場合は <http://localhost:5173> を開く。API は Vite のプロキシ経由で 7777 に飛ぶ。
`dev:api` は `go run . .` で自分自身のリポジトリを対象にしているので、このリポジトリの差分を
見ながら UI をいじれる。

開発中は `webdist/` が古いままでもよい（フロントは Vite が配るため）。`pnpm build` を通すと
作り直される。

### リリース

CI は使わず、手元でクロスコンパイルして GitHub Releases に上げる。

```bash
pnpm release v0.1.0   # dist/release に 4 プラットフォーム分の tar.gz と SHA256SUMS
gh release create v0.1.0 dist/release/*.tar.gz dist/release/SHA256SUMS \
  --title v0.1.0 --generate-notes
```

フロントは gzip して埋め込むので、`vite build` は 1 度で全プラットフォームに使い回せる。
`CGO_ENABLED=0` なのでクロスコンパイルに追加のツールチェインは要らない。

### 構成

```
main.go                引数処理 → サーバ起動 → ブラウザ起動
```

### API

| エンドポイント        | 内容                                                          |
| --------------------- | ------------------------------------------------------------- |
| `GET /api/diff`       | `DiffPayload`（patch 本体・ブランチ・ハッシュ・除外ファイル） |
| `GET /api/files`      | ファイラ用のパス一覧と git status                             |
| `GET /api/file?path=` | ファイルの中身                                                |
| `POST /api/stage`     | ステージへ入れる／から出す。**index を書き換える**            |
| `POST /api/discard`   | 未ステージの変更を捨てる。**取り消せない**                    |
| `GET /api/events`     | SSE。差分が変わると `event: change` が飛ぶ                    |
| その他                | `dist/web` の静的配信                                         |

`/api/file` のパスはブラウザから来るので、正規化に加えて `filepath.EvalSymlinks` で
リポジトリ外へ抜けていないことを確認している（シンボリックリンク対策）。

`/api/stage` のパスは `filepath.Clean` に任せない。`../../etc/passwd` が `etc/passwd` へ
化けて「リポジトリ内の存在しないパス」として通ってしまうので、`..` と絶対パスは明示的に弾く。

patch のパースはブラウザ側で `parsePatchFiles()` を使う。サーバは git の出力をそのまま渡すだけ。

## 現状の制約

- **見られるのはコミットしていない差分だけ**。`di main...HEAD` や `di HEAD~3`、`--staged` のような
  リビジョン指定には未対応。
- **コメントはブラウザの `localStorage` にしか残らない**。サーバにもファイルにも書かない。
  ブラウザやプロファイルを変えると見えないし、別端末とも共有されない。
- コメントは行番号に紐付いているだけなので、**その行が編集されるとズレる**。差分が変わっても
  行番号は追随しない。
- 返信スレッドと「解決済み」は無い。1 箇所 1 コメント。
- コメント本文は Markdown として描画しない（プレーンテキスト扱い）。
- **コードの編集はできない**。表示専用。
- ファイラは**閲覧専用**。作成・リネーム・削除・編集はできない。
- ファイラで開けるのは 1 度に 1 ファイル。タブやスプリットはない。
- バイナリと 1MB 超のファイルは中身を出さず、その旨だけ表示する。
- ツリーの `@pierre/trees` は beta 版（1.0.0-beta.6）。
- 差分モードのファイル一覧はフラットなリストのまま（ツリーはファイラ側だけ）。
- **認証なし、かつ破壊的操作あり**。`POST /api/stage` と `POST /api/discard` は誰でも
  叩けるので、`--host` で外に晒すと到達できる相手がリポジトリの index を書き換えたり、
  **作業内容を消したり**できる。読み取り専用ではない。`127.0.0.1` バインドが既定なのはそのため。
  確認ダイアログはブラウザ側の UI にしか無く、API には無い。
- hunk 単位・行単位のステージ／破棄は無い。commit / push もできない。
- トンネリング（Tailscale / ngrok など）の機能は持たない。`--host` でバインド先を指定するだけで、
  経路の用意は利用者側に任せている。
- 巨大な差分は `git diff` の出力を丸ごと JSON で送るので、初回ロードが重くなる。
  描画自体は CodeView が仮想化するので、ファイル数が多くても表示は軽い。
- 狭いウィンドウで `split` にすると右カラムが見切れる。`unified` に切り替えるか広げる。
- **新規追加だけのファイルは `split` と `unified` で見た目が変わらない**。削除行が無いので
  split の左カラムが空になるため。コミットが 1 つも無いリポジトリは全ファイルが新規扱いに
  なるので、どちらを選んでも同じに見える。
- ツリーの選択をプログラムから外す API が `@pierre/trees` に無いので、セクション表示に
  戻してもツリー側のハイライトは最後に開いたファイルに残る。
- ポートの競合は `--port` を明示したときだけ起こる。既定はカーネルに空きポートを選ばせる
  ので、いくつ同時に起動しても衝突しない。埋まっていた場合は起動せずエラーで終わる（exit 1）。
  なお `127.0.0.1:7788` と `100.94.126.82:7788` はバインドアドレスが違うので共存できる。
- Chromium でしか確認していない（Safari / Firefox 未検証）。
- API の型は Go の構造体（`git.go`）と TypeScript（`src/shared/types.ts`）に**二重で定義**して
  いる。片方だけ直すと静かにずれる。

## 動作確認済みの範囲

macOS 15 / Node 24.13 / Chromium（Playwright）で確認した。

- tracked（staged + unstaged）と untracked が 1 本の patch にまとまって表示される
- `split` / `unified` の切り替え、シンタックスハイライト、ライト/ダーク自動切り替え
- サイドバーのクリックでその diff へスクロール
- 仮想化（17 ファイル・スクロール高 2396px に対し、描画は可視範囲のみ）
- ファイルを新規作成すると 1〜2 秒でサイドバーと本体に自動で現れる
- git リポジトリ外・不正オプションのエラーメッセージ
- `--host <Tailscale IP>` でバインドし、MagicDNS 名（`*.ts.net:7788`）から到達できること
- 行番号クリック → コメント入力 → 保存 → diff 内とサイドバーに表示
- `コピー` でクリップボードに `パス:行数 コメント` 形式（複数行本文のインデント込み）が入ること
- リロード後もコメントが残ること（localStorage）
- ツリーからファイルを開くと、変更の有無にかかわらず全文が出ること
- アクティビティバーでビューが切り替わり、選択中のアイコンをもう一度押すと
  パネルが閉じてレールだけになること（再読み込みしても状態が残ること）
- 「ステージ済み」「変更」の見出し左の `⌄` で、その一覧だけ畳めること
- 見出しの `ステージ済み` / `変更` で表示が切り替わり、両方に変更があるファイルで
  それぞれ別の差分が出ること（`git diff --cached` と `git diff` に一致すること）
- `split` / `unified` の切り替えが単体ファイル表示でも効くこと（`data-diff-type` で確認）
- ツリーで付けたコメントが、コメント一覧・コピー結果にも入ること
- ヘッダの `⌄` でそのファイルだけ折りたためること（行数 30 → 0 → 30）
- `表示済み` を押すと自動的に畳まれ、進捗が `1/17` と出ること
- `全部たたむ` / `全部開く` が切り替わること
- ガターの「+」クリックで 1 行、ドラッグで範囲のコメントが作れること
  （`src/app.ts:8-9 この2行まとめて直したい` をクリップボードで確認）
- `/api/file` が `../../../etc/passwd` や `/etc/passwd` を弾くこと
- 単一バイナリ（7.9MB）を Node の無いディレクトリへコピーして動かせること
- ステージ操作（1 件 / 一括 / 解除、未追跡ファイル込み）が UI と `git status` の両方で一致すること
- `/api/stage` が `../../../etc/passwd` `/etc/passwd` `src/../../escape` `.` を弾くこと
- 破棄が状態ごとに正しく効くこと（変更→復元 / 削除→復活 / 未追跡→削除 / ステージ済み→無傷）
- 破棄の確認ダイアログでキャンセルすると何も起きないこと
- 静的ファイルが `Content-Encoding: gzip` で返り、gzip 非対応でも展開して返せること
- 非セキュアコンテキスト（`http://<Tailscale IP>`）でのコメント保存とコピー
- ポーリングの実測値（定常時 17ms / 変更後の `collectDiff` 35ms）
- コメント追加時・ライブリロード時に、無関係なファイルの DOM が作り直されないこと
- ワーカープールが 4 本立ち上がり、ハイライトが従来どおり効くこと

iOS Safari だけは手元で検証できていない。`execCommand` によるコピーが拒否された場合は、
サイドバーに選択済みの textarea が出るので手動でコピーできる。
